# 真实入口加载进度（2026-09-21）

原进度条仅在 HTML 设置 value=0，没有任何 JavaScript 赋值，入口加载完成就直接隐藏，因此始终不动。

修复：用初始模块清单及去重后的共享贴图字节数作为固定分母（约 3.49 MB）。GLTFLoader 的 ProgressEvent 更新模型字节，专用 LoadingManager 的资源完成事件补齐贴图或缓存命中；失败资源的 itemEnd 不算成功。初始模块计划与实际 init 共用同一模块列表。后台房间下载不重置入口进度。清单读取和画面准备使用无百分比活动指示，完成实际首次渲染后再隐藏。

验证：

- check-loading-progress.mjs：固定分母、共享贴图去重、乱序事件单调性、缓存完成、字节上限、阶段变化、失败资源和后台事件隔离通过。
- Chrome 限速 500,000 bytes/s、60 ms 延迟、禁用缓存：观察到 70 个不同的下载百分比，实际从 0% 达到 100%，随后进入准备画面阶段；页面错误 0。
- 正常重载：入口完成后隐藏，最终 value=100。
- 注入基础 GLB 的 HTTP 503：显示加载失败和重新加载按钮，隐藏进度条。
- npm run build 与资源预算检查通过。

证据：loading-progress.png、loading-progress-browser.json。百分比度量的是入口模型与贴图，JS、解码器和可选光影初始化不在该字节分母中；后者由准备阶段覆盖。未使用定时器增加进度。
